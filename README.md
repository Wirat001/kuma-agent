# Kuma Agent

A lightweight heartbeat agent for [Uptime Kuma](https://github.com/louislam/uptime-kuma).

Kuma Agent is designed for homelab servers and Linux machines. It periodically sends a heartbeat to an Uptime Kuma Push Monitor so you can detect when a server goes offline, becomes unreachable, or stops sending heartbeats.

## Features

* Lightweight and simple
* Uses `curl` to send heartbeat requests
* Runs automatically with `systemd`
* Sends a heartbeat every 60 seconds
* Starts automatically after reboot
* Automatically uses the machine hostname
* Stores the Kuma token in a protected configuration file
* Easy one-command installation
* Easy uninstall

## Requirements

* Linux with `systemd`
* `curl`
* Root or `sudo` access
* An Uptime Kuma Push Monitor
* Network access to your Uptime Kuma server

## Installation

### 1. Create a Push Monitor in Uptime Kuma

In Uptime Kuma:

1. Click **Add New Monitor**
2. Select **Push**
3. Enter a monitor name, for example:

```text
PVE2 - Heartbeat
```

4. Set the heartbeat interval to:

```text
60 seconds
```

5. Save the monitor.
6. Copy the Push Token generated by Uptime Kuma.

> Keep the Push Token private. Do not publish it in GitHub.

### 2. Install Kuma Agent

Run:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "YOUR_PUSH_TOKEN"
```

Replace:

```text
YOUR_PUSH_TOKEN
```

with the Push Token from Uptime Kuma.

The installer automatically detects the hostname of the machine.

For example:

```text
pve1
pve2
truenas
frigate
```

## What the Installer Creates

The installer creates:

```text
/etc/kuma/heartbeat.conf
/usr/local/bin/kuma-heartbeat.sh
/etc/systemd/system/kuma-heartbeat.service
/etc/systemd/system/kuma-heartbeat.timer
```

### Configuration

The Kuma URL and Push Token are stored in:

```text
/etc/kuma/heartbeat.conf
```

The file is protected with:

```text
chmod 600
```

so only root can read it.

### Heartbeat Script

The agent sends a request to:

```text
https://monitor.wirat.ovh/api/push/<TOKEN>
```

every 60 seconds.

## Check Agent Status

Check the timer:

```bash
systemctl status kuma-heartbeat.timer
```

Check the next scheduled run:

```bash
systemctl list-timers kuma-heartbeat.timer
```

Manually test the heartbeat:

```bash
systemctl start kuma-heartbeat.service
```

Check the service result:

```bash
systemctl status kuma-heartbeat.service
```

View logs:

```bash
journalctl -u kuma-heartbeat.service -n 50
```

## How It Works

```text
┌─────────────────────┐
│ Linux Server        │
│                     │
│ Kuma Agent          │
│        │            │
│        │ 60 seconds │
└────────┼────────────┘
         │
         │ HTTPS Push
         ▼
┌─────────────────────┐
│ Uptime Kuma         │
│                     │
│ Push Monitor        │
└─────────────────────┘
```

If the server stops sending heartbeats, Uptime Kuma can mark the monitor as **DOWN** and send notifications.

## Multiple Servers

You can install the agent on multiple machines.

Create a separate Push Monitor and token for each server.

Example:

```text
PVE1      → PVE1 - Heartbeat
PVE2      → PVE2 - Heartbeat
TrueNAS   → TrueNAS - Heartbeat
Frigate   → Frigate - Heartbeat
AdGuard   → AdGuard - Heartbeat
Win11     → Win11 - Heartbeat
```

Then install the same script on each machine using its own token:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "PVE1_TOKEN"
```

Another machine:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "PVE2_TOKEN"
```

## Uninstall

Run:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-uninstall.sh \
| sudo bash
```

This removes:

```text
kuma-heartbeat.timer
kuma-heartbeat.service
kuma-heartbeat.sh
/etc/kuma/
```

## Security

The Push Token is a secret.

Do not:

* Commit tokens to GitHub
* Put tokens inside the installation script
* Share tokens publicly
* Use the same token for unrelated servers

The token should only be supplied during installation:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "YOUR_PUSH_TOKEN"
```

## Project Status

This project currently focuses on **heartbeat monitoring**.

It does not collect detailed system metrics such as:

* CPU usage
* RAM usage
* Disk usage
* Disk I/O
* Network traffic
* Temperature
* SMART information
* NVMe health
* Docker statistics
* Proxmox VM/LXC metrics

For detailed metrics, a future monitoring stack such as **Prometheus + Grafana** can be used alongside Uptime Kuma.
