# Uptime Kuma Agent

Simple heartbeat agent for [Uptime Kuma](https://github.com/louislam/uptime-kuma).

This agent sends a heartbeat from a Linux server to Uptime Kuma every 60 seconds using a systemd timer.

It is designed for monitoring servers, Proxmox hosts, Docker hosts, VPS, NAS, Raspberry Pi, ARM devices, and other Linux machines.

## Features

* Simple one-command installation
* Uses Uptime Kuma Push Monitor
* Sends heartbeat every 60 seconds
* Runs as a systemd service + timer
* Starts automatically after reboot
* Works on x86_64 and ARM Linux
* Stores the Push URL securely with permission `600`
* No Docker required
* Lightweight and minimal resource usage
* Easy to remove

---

## Requirements

* Linux system
* `systemd`
* `curl`
* Root access / `sudo`
* Uptime Kuma with a **Push Monitor**

## 1. Create a Push Monitor

Before installing the agent, create a monitor in Uptime Kuma.

In Uptime Kuma:

1. Click **Add New Monitor**
2. Select **Push**
3. Set a name, for example:

```text
arm-64
```

4. Set Heartbeat Interval:

```text
60 seconds
```

5. Click **Save**

After saving, copy the complete **Push URL**.

It should look similar to:

```text
https://monitor.example.com/api/push/TOKEN?status=up&msg=OK&ping=
```

> Important: The Push Monitor must be saved and active before testing the agent.

## 2. Install

Run:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "FULL_PUSH_URL"
```

Example:

```bash
curl -fsSL https://raw.githubusercontent.com/Wirat001/kuma-agent/main/kuma-install.sh \
| sudo bash -s -- "https://monitor.example.com/api/push/xxxxxxxx?status=up&msg=OK&ping="
```

Replace the URL with your own Uptime Kuma Push URL.

### Why use the full Push URL?

The installer accepts the complete URL generated by Uptime Kuma.

This means you don't need to manually separate:

* Kuma URL
* Push token
* Status
* Message
* Ping parameters

Just copy and paste the complete Push URL.

## 3. What the installer creates

The installer creates:

```text
/etc/kuma/heartbeat.conf
/usr/local/bin/kuma-heartbeat.sh
/etc/systemd/system/kuma-heartbeat.service
/etc/systemd/system/kuma-heartbeat.timer
```

### Configuration

```text
/etc/kuma/heartbeat.conf
```

Example:

```ini
PUSH_URL="https://monitor.example.com/api/push/TOKEN?status=up&msg=OK&ping="
NAME="arm-64"
```

The configuration file is protected with:

```text
chmod 600
```

## 4. Check the Agent

Check the timer:

```bash
systemctl status kuma-heartbeat.timer --no-pager
```

Expected:

```text
Active: active (waiting)
```

Check the timer schedule:

```bash
systemctl list-timers kuma-heartbeat.timer
```

Check the heartbeat service:

```bash
systemctl status kuma-heartbeat.service --no-pager
```

The heartbeat service is a `oneshot` service, so it normally returns to:

```text
Active: inactive (dead)
```

after successfully sending the heartbeat.

This is normal.

The timer is what runs it every 60 seconds.

## 5. Test Manually

Load the configuration:

```bash
source /etc/kuma/heartbeat.conf
```

Then test the Push URL:

```bash
curl -sS "$PUSH_URL"
```

A successful request should return:

```json
{"ok":true}
```

You can also test through systemd:

```bash
systemctl start kuma-heartbeat.service
```

Then check:

```bash
systemctl status kuma-heartbeat.service --no-pager
```

## 6. Troubleshooting

### `404 Not Found`

If you see:

```text
curl: (22) The requested URL returned error: 404 Not Found
```

and:

```json
{"ok":false,"msg":"Monitor not found or not active."}
```

The server can reach Uptime Kuma, but the Push Monitor cannot be found or is not active.

Check:

1. The Push Monitor exists in Uptime Kuma
2. The Push Monitor has been **saved**
3. The Push Monitor is active
4. The Push URL in `/etc/kuma/heartbeat.conf` is correct
5. The Push token belongs to this monitor

Check the current configuration:

```bash
cat /etc/kuma/heartbeat.conf
```

Then test:

```bash
source /etc/kuma/heartbeat.conf
curl -sS "$PUSH_URL"
```

If it returns:

```json
{"ok":true}
```

the Push URL is working.

---

### Check service logs

```bash
journalctl -u kuma-heartbeat.service -n 50 --no-pager
```

Follow the logs:

```bash
journalctl -u kuma-heartbeat.service -f
```

---

### Check timer logs

```bash
journalctl -u kuma-heartbeat.timer --no-pager
```

## 10. Monitoring Architecture

The agent is intended to monitor the availability of Linux machines.

For example:

```text
                    Internet
                       │
                       ▼
              ┌─────────────────┐
              │  Uptime Kuma     │
              │ monitor.wirat.ovh│
              └────────┬────────┘
                       │
          ┌────────────┼────────────┐
          │            │            │
          ▼            ▼            ▼
       PVE1          PVE2         ARM-64
       Push          Push          Push
          │            │            │
          ▼            ▼            ▼
       Server        Server       Server
```

Each machine should have its own Uptime Kuma Push Monitor and Push URL.

Example:

```text
PVE1    → Push Monitor → PVE1 Push URL
PVE2    → Push Monitor → PVE2 Push URL
ARM-64  → Push Monitor → ARM-64 Push URL
TrueNAS → Push Monitor → TrueNAS Push URL
Frigate → Push Monitor → Frigate Push URL
```

This makes it possible to identify which machine stopped sending heartbeats.

## Security

The Push URL contains a secret token.

Do not publish your Push URL in:

* GitHub
* README files
* Screenshots
* Public forums
* Chat messages
* Logs

If a Push URL is accidentally exposed, create a new Push Monitor / Push URL in Uptime Kuma and replace the old one.

The agent stores the Push URL in:

```text
/etc/kuma/heartbeat.conf
```

with permissions:

```text
600
```

## How It Works

Every 60 seconds, systemd starts:

```text
kuma-heartbeat.service
```

which executes:

```text
/usr/local/bin/kuma-heartbeat.sh
```

The script sends an HTTPS request to the Uptime Kuma Push URL.

The timer then waits for the next interval.

```text
systemd timer
     │
     │ every 60 seconds
     ▼
kuma-heartbeat.service
     │
     ▼
kuma-heartbeat.sh
     │
     ▼
Uptime Kuma Push API
     │
     ▼
Monitor = UP
```

If the machine shuts down, loses network connectivity, or the heartbeat stops, Uptime Kuma can detect the missed heartbeat.
